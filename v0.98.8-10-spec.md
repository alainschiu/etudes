# v0.98.8–10 — The Score Trilogy (combined spec)

> **Drafted 2026-06-15**, grounded in `main` at v0.98.7 (`612c27b`) and the PDF audit of the same date. Decisions locked by Alain 2026-06-15: (1) fullscreen/flash → release 1; (2) annotation → v0.98.10, gated on difficulty; (3) notes-per-bookmark → release 1; (4) container-gating **approved** (Alain + UI staff) — the score viewer gates features on container space, `useViewport` untouched; (5) link migration upfront. Also **approved**: badge-tap-always-jumps with a separate edit affordance (F2). This spec is fully decision-locked; implementation commences W28 Monday. Authority: `North_Star_V2.5.md`. This document specs all three releases **in one go** because several decisions cascade across them — the shared conventions in Part 0 are the contract that every release must honor, so no release forces a re-migration or re-architecture of an earlier one.
>
> **New finding since the audit:** `spot.pdfPage` never survives a reload — `migrateItems` (`src/lib/migrations.js`, spot mapping) rebuilds spots from an explicit field list that omits `pdfPage`, and it runs on every load/cloud-apply/import. The bare-page link mechanism is broken at rest; only the bookmark mechanism persists. The v12 unification is therefore also a bug fix, and there is almost no durable `pdfPage` data in the wild to migrate.

Three releases:

| Version | Name | Theme | Schema |
|---|---|---|---|
| v0.98.8 | Score linking + durability | The differentiator works from anywhere; scores can't silently vanish | **12** (scoreLink + bookmark.note) |
| v0.98.9 | Viewer polish | The viewer stops being a reason to leave | unchanged |
| v0.98.10 | Marking *(conditional)* | Light practice-aware marks on the score | unchanged (marks are device-local) |

v0.98.10 exists only if it passes its gate (see Part 3). If cut, the slot vanishes and the run continues to v0.99.0.

## Part 0 — Shared conventions (the cross-release contract)

These eight decisions are load-bearing across all three releases. Each is cheap to honor now and expensive to retrofit. **Do not deviate in any release without amending this spec.**

**C1. The unified link shape.**
`spot.scoreLink = null | { attId, bookmarkId, page }` — `attId` (attachment id) always present; exactly one of `bookmarkId` / `page` meaningful. If `bookmarkId` is set it wins and the bookmark's page is resolved **at jump time** (the link follows bookmark edits); `page` is the direct fallback. Every editor (Today `SpotRow`, Repertoire `SpotEditor`, PdfDrawer spots tab) reads and writes this one field. No surface may reintroduce a bare unqualified page.

**C2. Pages are absolute PDF page numbers, everywhere.**
`scoreLink.page`, bookmark `page`, jump targets, and (v0.98.10) mark keys all store the **absolute** page of the PDF file. Attachment page-ranges (`startPage`/`endPage`) are presentation/navigation aids only. If display copy ever shows a range-relative number, it is computed at render, never stored. (Rationale: one blob serves many items with different ranges; a stored relative page is ambiguous the moment a second item attaches the same PDF.)

**C3. One generic open-score channel.**
v0.98.8 introduces `requestScoreView({itemId, attId?, page?, bookmarkId?})` at App level: sets `pdfDrawerItemId` and hands PdfDrawer a pending target it consumes once the document reports loaded. Spot-tap (98.8), "jump to bookmark from elsewhere" (future), and "jump to mark" (98.10) all ride this channel. Do not build feature-specific variants; extend the payload.

**C4. Storage doctrine (extends CLAUDE.md's table).**
- Score **links** + **bookmark notes**: part of `items` in synced JSON (small, textual — Supabase + export like everything else).
- Score **blobs**: IndexedDB `pdfs`, device-local, Drive backup — unchanged.
- Score **marks** (98.10): device-local IndexedDB (new store `marks`), keyed by `(libraryId, page)`; backed up via Drive alongside blobs; **never** in the Supabase JSON payload (size + doctrine: pixels/vectors are traces, like audio).

**C5. Marks are keyed by `libraryId`, not attachment or item.**
One PDF blob can be attached to several pieces. A fingering circled while practicing Piece A must be visible when Piece B opens the same score. `(libraryId, absolutePage)` is the identity; attachments/items are views onto it.

**C6. The fullscreen–modal rule.**
The Fullscreen API hides every DOM node outside the fullscreened subtree. App-level modals (`ConfirmModal`, `PromptModal`) render outside `PdfDrawer` — so **any action inside the fullscreen viewer that would open an app-level modal must first exit fullscreen**, or use a drawer-local inline confirm rendered inside the drawer subtree. This binds v0.98.8 (delete/remove confirms reachable from the drawer) and v0.98.10 (mark tools). Violating it = invisible modal = app appears frozen. Test it explicitly in both releases.

**C7. The per-page wrapper is sacred.**
Every rendered `Page` sits in a `position:relative` wrapper (today it anchors `BookmarkRibbon`). The flash fix (98.8), virtualization (98.9), and the mark overlay (98.10) all attach to this wrapper. Whatever restructuring a release does to the render path, the wrapper — one per visible page, positioned, carrying `data-page` — survives.

**C8. One hidden-render utility, two consumers.**
The flash fix (98.8, single/spread modes) pre-renders the adjacent page hidden; virtualization (98.9, continuous mode) renders a window of pages around the viewport. Both need "render page N without displaying it." Build the capability once in 98.8 with 98.9's windowing in mind — 98.9 must not rewrite 98.8's render path, only widen the window logic.

## Part 1 — v0.98.8 "Score linking + durability"

The heavy release: schema bump + iOS device work + a data-durability change. v0.98.6-level care. Six fixes, one commit each.

### F1. Unified `scoreLink` + bookmark `note` — schema v12

**Current:** two parallel link mechanisms — `spot.pdfPage` (bare page, not attachment-qualified, **stripped on every reload** by `migrateItems`) and `spot.bookmarkId`+`spot.pdfAttachmentId` (qualified, settable only in Repertoire's `SpotEditor`). Bookmark shape is `{id,name,page}` (`useEtudesState.js:523`), no note field.

**Fix:**
- Add `scoreLink` per C1. Extend `migrateItems`' spot mapping (unconditional idempotent, house pattern): `bookmarkId+pdfAttachmentId` → `{attId, bookmarkId, page:null}`; a surviving `pdfPage` (import payloads may carry one) → `{attId: item.defaultPdfId || first attachment || null, bookmarkId:null, page}`; if `attId` resolves to null, drop the link (a link to no attachment is dead weight). Remove `pdfPage`/`bookmarkId`/`pdfAttachmentId` from the mapped output. Bookmarks gain `note:''` default in the same pass.
- `IMPORT_MIGRATIONS` gains `{from:11,to:12}` doing the same to import payloads. `SCHEMA_VERSION=12` in `config.js`.
- All three spot editors converge on `scoreLink`: the page editor writes `{attId, page}`; the bookmark `<select>` (extend beyond Repertoire if cheap, else 98.9) writes `{attId, bookmarkId}`.

**Constraints:** migration idempotent, tested on fresh / v0.98.7-with-bookmark-links / no-PDF states. `structurallyEqual` needs no change (shape diff on first cross-device sync is the same class v0.98.6 handled; `migrateItems` runs on cloud-applied state too). Never store range-relative pages (C2).

### F2. The bridge — tap a spot anywhere, the score opens and jumps

**Current:** navigation fires only inside an already-open drawer (auto-jump effect `PdfDrawer.jsx:235-252`; badge-tap `:506`). `jumpToPageRef` is declared (`:108`) with zero providers. Outside the drawer, the `SpotRow` badge opens the page *editor* (`shared.jsx:446`).

**Fix:** implement `requestScoreView` (C3). `SpotRow`/`SpotEditor` badge tap → `requestScoreView({itemId, ...spot.scoreLink})`. PdfDrawer consumes the pending target: select the attachment (`setActivePdfId(attId)`), then jump once loaded (F3). Retire `jumpToPageRef` — one mechanism, not two. Auto-jump on spot activation stays, rewritten onto the same pending-target path.

**UI (per the staff note):** badge tap = jump, everywhere. Editing the link moves to a distinct affordance (pencil beside the badge / inside the spot's editor area) that must be reachable without hover on touch (same pattern as existing spot controls). Empty state: no link → tap opens the link editor (nothing to jump to).

### F3. Jump race — onLoad-gated with retry

**Current:** two `setTimeout(...,80)` jumps (`PdfDrawer.jsx:246,250`); on cold load / large PDF / continuous mode the target page isn't mounted and the jump silently no-ops.

**Fix:** pending-jump state cleared only on success: attempt on `onDocLoaded` and again on page-mount (continuous), bounded retries, then give up silently (NS: no error toast for a navigation). Applies to both the bridge (F2) and spot-activation auto-jump.

### F4. Storage durability

**Current:** `navigator.storage.persist()` never called; `addPdfToItem` (`useEtudesState.js:466-484`) ignores `idbPut`'s return — a quota-failed upload looks fine until reload; the placeholder copy blames "another device."

**Fix:**
- Request `navigator.storage.persist()` once at boot (with `isDriveConfigured` etc. in `App.jsx`); record the result; surface it as a quiet status line in the Sync tab storage block (voice: "Storage is protected from cleanup." / "Storage may be cleared under pressure. Back up to Drive.").
- `addPdfToItem` honors the return: on failure, do **not** add the attachment; confirm-modal in NS voice: "Could not store the score on this device." Audit sibling ignored-return sites (`uploadRefTrack`, piece-recording writes) — same class; fix if cheap, else log for v0.99.1.
- Placeholder copy split: metadata-without-blob now reads as "Score not stored on this device." (true both for other-device and evicted cases) with the existing Drive-restore path alongside.

**Constraint:** this is the v0.98.6 honesty pattern (no silent fallback, caller can react). Don't change the `etudes-storage-full` flow.

### F5. Notes per bookmark

**Fix:** `note` field shipped in F1's migration. UI: small editor in the bookmark popover (`PdfViewer.jsx:469-491` add-form area) and the drawer bookmarks tab; note text appears in the jump list under the name and in the ribbon `title`. `MarkdownField`, minHeight small — house prose standard (cheap post-v0.98.7). Wiki props threaded (PdfDrawer already receives them).

**Constraint:** C6 — the popover renders via portal into `document.body`; in fullscreen it must portal into the fullscreened element instead (or the popover is invisible). Verify explicitly.

### F6. Focused reading — fullscreen + page-turn flash + fit-to-page

**Current:** "expand" is CSS maximization inside the overlay (`PdfDrawer.jsx:126,261-263`) — browser chrome remains in Safari tabs; drawer resize handle hidden while expanded (`:623`). Page turns remount `<Page>` → white flash. Fit-to-page hidden behind `!isMobile` (`PdfViewer.jsx:283`).

**Fix:**
- **Fullscreen:** Fullscreen API on the drawer's content element where supported (desktop; iPad ≥ iPadOS 16.4); iPhone keeps the maximized overlay (platform limit — element fullscreen unsupported). Expand button becomes "enter fullscreen" with overlay fallback. Exit restores prior size. **C6 applies from this commit on.**
- **Flash:** dual-mount swap — outgoing page stays until incoming `onRenderSuccess`; pre-render adjacent page hidden (C8 utility). Single + spread modes.
- **Fit-to-page:** remove the `!isMobile` gate — available everywhere (first slice of container-gating; the rest lands in 98.9/P8).

### v0.98.8 verification (real device, iPad + iPhone)

1. Migration triad: fresh / v0.98.7-with-bookmark-links / no-PDF → links land as `scoreLink`, bookmarks gain `note:''`, idempotent on second load, `SCHEMA_VERSION` 12.
2. Today, score **closed**, tap a linked spot's badge → score opens on the **right attachment** (multi-PDF item) at the **right page**, including cold load (no page-1 stall).
3. Reload → link still present (regression test for the strip bug).
4. Bookmark edit moves its page → linked spot jumps to the new page (C1 semantics).
5. Fill storage / simulate `idbPut` failure → upload rejected with the NS-voice message, no ghost attachment, reload shows no phantom.
6. `navigator.storage.persist()` requested; Sync tab shows the status line.
7. Bookmark note: create, edit, shows in jump list; round-trips export/import.
8. iPad fullscreen: enter/exit; **trigger a destructive confirm from inside fullscreen → modal is visible** (C6).
9. Page turns: no white flash, single + spread; zoom preserved across turns.
10. Fit-to-page on iPhone + iPad-portrait.

## Part 2 — v0.98.9 "Viewer polish"

No schema change. One commit per fix. All five are Tier-2 audit items; device-verified as one cluster.

- **P3 — persist reading prefs.** `{zoom, fitMode, mode}` → `localStorage` `etudes-pdfPrefs` (global, not per-attachment — one player, one reading habit; revisit if dogfooding disagrees). Restore on drawer mount. `expanded`/fullscreen stays per-session.
- **P5 — wheel scrolls the zoomed page.** In single/spread with content overflowing, wheel scrolls within the page; flips only at scroll edges (accumulator preserved). Continuous unchanged.
- **P6 — virtualize continuous mode.** Windowed rendering (viewport ± N pages) using the C8 utility; placeholder boxes sized from `pageSize` keep scroll geometry stable. **C7: the per-page wrapper with `data-page` survives virtualization** — the 98.10 overlay depends on it.
- **P7 — export fixes.** `uniqueSlug` in the scores loop (two PDFs on one item currently overwrite — `useImportExport.js:433`); `libraryId → filename` map + `etudes-pdfLibrary` in `_data.json`; a readable "Score links" section in each item's `.md` (spot → file + page, bookmark list **including notes** — closes the one-release gap where bookmark notes exist but aren't human-readable); pages written absolute (C2).
- **P8 — container-gating + spread pairing.** Spread offered when the viewer container ≥ ~700px wide (iPad-portrait qualifies; iPhone doesn't; desktop unchanged); pairing gains an odd/even offset toggle so music openings land on the correct seam (persisted with P3's prefs); drawer resize handle works on touch (pointer events) on iPad both orientations; stays hidden on phones. **`useViewport` itself is untouched** — app-wide rule preserved byte-for-byte.

**Verification:** prefs survive close/reopen; zoomed-page scroll + edge-flip; 200-page score scrolls continuous without memory spike (iPad Safari); export ZIP with two PDFs on one item → both files present, `.md` shows links + bookmark notes; iPad-portrait: spread available, resize drag works, correct seam with offset; desktop identical to v0.98.8.

## Part 3 — v0.98.10 "Marking" (conditional)

**The gate (decide after v0.98.9 ships, from Alain's practice notes):** build only if marking is still make-or-break once spot-links + bookmark-notes are in daily use. If linking covers the need → cut to v1.x, slot vanishes, straight to v0.99.0.

**Scope if built (light, deliberately not ForScore):**
- Two tools: **highlight rectangle** and **freehand ink**. One stroke width. **Undo** (stack per page-session), no eraser v1.
- Marks stored in **normalized page coordinates** (0–1 × 0–1 of the page box) so they're zoom/fit/rotation-independent; rendered as an SVG overlay in the per-page wrapper (C7).
- Persistence: IndexedDB store `marks`, key `(libraryId, page)` (C4/C5); saved on stroke-end with the honest-failure pattern from F4; covered by `navigator.storage.persist()`.
- Drive backup: marks ride the blob backup path; `driveManifest` gains an additive field (existing forward-compatible policy).
- Export: marks in `_data.json` (re-importable). A humanly readable form (burning marks into PDF copies) is **explicitly out of scope** — flagged as an NS open question for the print/PDF track.
- Toolbar: two toggles + undo in the existing viewer toolbar; tools only in fullscreen/expanded reading (proposal — keeps the small-drawer toolbar quiet); C6 applies to any dialog.

**Open NS question — mark color (Alain decides before build):** the palette is IKB + gold, neither is a natural pencil. Options: (i) **gold at reduced opacity** — inside the existing vocabulary; marking-as-preservation adjacent to locked recordings; (ii) **a dedicated "graphite" material token** added to `src/constants/theme.js` — arguably material rather than a third accent, but it is an NS Evolution call and must be made deliberately, not defaulted. The spec intentionally does not choose.

**Difficulty honesty:** medium — a full release. The risk is not the data model (small) but input quality on iOS (Pencil vs finger, palm rejection, scroll-vs-draw disambiguation). Prototype the input layer first; if it can't be made to feel right in a few days, that is the gate failing — cut without guilt.

## Cascade risks — why this is one spec

| # | Risk | Binds | Mitigation in this spec |
|---|---|---|---|
| R1 | `scoreLink` shape wrong → second migration | 98.8 → all | C1/C2 fixed now; attachment-qualified + absolute pages from day one |
| R2 | Page-number convention drift (absolute vs range-relative) between link, export, marks | 98.8 → 98.9 → 98.10 | C2: absolute stored everywhere, relative is render-only |
| R3 | Marks keyed to attachment/item → same PDF shows different marks per piece | 98.10 (decided by 98.8's model talk) | C5: `(libraryId, page)` identity, recorded now |
| R4 | Feature-specific jump paths multiply (spot-jump vs bookmark-jump vs mark-jump) | 98.8 → 98.10 | C3: one `requestScoreView` channel; `jumpToPageRef` retired |
| R5 | Fullscreen hides app-level modals → "app frozen" reports | 98.8 → 98.10 | C6 rule + explicit verification step in both releases |
| R6 | 98.9 virtualization rewrites the render path 98.8's flash fix just built; 98.10's overlay loses its anchor | 98.8 → 98.9 → 98.10 | C7 (wrapper survives) + C8 (one hidden-render utility, windowing-aware from 98.8) |
| R7 | Marks in the Supabase payload → sync balloons past the 500 KB warning | 98.10 | C4 doctrine: marks device-local + Drive, never synced JSON |
| R8 | Bookmark notes ship (98.8) before the readable-export fix (98.9) → one release where notes aren't in the `.md` archive | 98.8 → 98.9 | Accepted knowingly (notes are in `_data.json`); P7 closes it; do not let P7 slip out of 98.9 |
