# v0.98.6 — Trust + Defaults

> **Revised 2026-06-10** to absorb the deliberation decisions in [[Gate-A-Writing-Surfaces_2026-06-10]] and [[Roadmap v0.99.1]]. Changes from the Jun-8 draft: Fix 1 is now the **real persistence fix** (per-note keys, hybrid plan C), not the indicator-only version that was overruled; **W2/W8** (shared wiki-link fix) and **W7** (viewport-fit) are pulled in; the storage-key allowlist is corrected from kebab-case to the actual camelCase keys. Authority is `North_Star_V2.5.md` (repo). Trust is the product's first promise — that framing drives Fix 1.

Six fixes addressing **silent data loss**, **wiki-link correctness**, **PWA shell**, and **friction defaults** on writing surfaces:

1. **Real persistence + honest autosave indicator (W1)** — per-note keys so one large note can't sink the whole journal; `lsSet` returns false on failure; an indicator that reflects true on-disk state. The IDB fallback is the deferred v0.99.x escalation (plan C).
2. **Shared wiki-link rendering fix (W2/W8)** — dead links render dimmed and non-clickable; back-port the NotesView `<span>` hardening into shared `MarkdownComponents`, removing the live `wikilink://` iOS scheme hazard. Done here so the v0.98.7 conversions inherit it.
3. **viewport-fit=cover (W7)** — make the existing safe-area insets resolve in standalone iOS. Shell-level, zero re-hardening risk.
4. **Notes `updatedAt` field** with schema migration — gives `mergeStates` something to compare for last-write-wins.
5. **LogBookPanel sections default open when content exists** — Pinned notes and Log book auto-expand if `item.detail` / `item.noteLog` has content.
6. **Mobile reflection auto-opens when content exists or day is closed** — TodayMobile reflection block, currently collapsed by default.

Sequence (smallest, lowest-risk first): ship 5 and 6 (pure UI defaults), then 3 (one-line shell fix), then 2 (shared component), then 4 and 1 together (both touch storage and the v11 migration — coordinate them). One commit per fix on the same branch. CHANGELOG sub-section `[0.98.6] — Trust + Defaults`.

The sync-hardening invariants from CLAUDE.md are load-bearing for fixes 1, 2, and 4.

## Why this release exists

The journal must not lie about whether the user's writing is preserved, and it must not lose it. Three known liars and one real loss path:

- TodayMobile's reflection block shows *"Saved"* whenever the field has text, even if `localStorage.setItem` threw a quota error (`TodayView.jsx:892-894`). Users trust the word. It doesn't mean what they think.
- **The journal actually loses notes near quota.** `etudes-freeNotes` is one JSON blob; one large note pushes the whole slice over quota, the first failure flips a global flag routing *every* surface to memory, and `lsSet` returns true so nothing reacts. On reload the writing is gone. This is the single most important fix in the release — trust is the product's first promise.
- Dead wiki-links render as live blue clickable links in several read surfaces, and on iOS the live `wikilink://` anchor is a scheme-navigation hazard. The connective tissue must be nearly perfect.
- In standalone PWA mode the safe-area insets silently resolve to zero (missing `viewport-fit=cover`), so the TopBar sits under the notch and the home indicator overlaps the footer and edit sheet.

Plus two friction defaults that compound — a needless tap to see piece notes, and the daily reflection hidden behind a chevron every evening. Each is a single line.

## Fix 5 — LogBookPanel sections default open when content exists

*(unchanged from the Jun-8 draft — verified still accurate)*

### Current state

`RepertoireView.jsx:463-464`:

```js
const [pinnedOpen,setPinnedOpen]=useState(false);
const [logOpen,setLogOpen]=useState(false);
```

Both default closed regardless of whether `item.detail` or `item.noteLog` has content.

### The fix


- Don't change LogBookPanel's surrounding markup or other state.

2. Expand a piece with no detail → collapsed.
3. Same for log entries vs none.
4. Collapse, switch pieces, return → respects original auto-state (re-mount).
5. Within one view: collapse → expand → collapse toggles as before.

## Fix 3 — viewport-fit=cover (W7)

### Current state

`index.html:13`:

```html
<meta name="viewport" content="width=device-width, initial-scale=1.0">
```

The app uses `env(safe-area-inset-*)` throughout (TopBar, Footer, Drawer, UpdatePrompt, edit sheets). Without `viewport-fit=cover`, iOS resolves those `env()` values to **0** in standalone mode (the CSS fallbacks do not fire — `env()` is supported, it just returns 0). With the `black-translucent` status bar, the TopBar sits under the notch and the home indicator overlaps the footer and the bottom of the note edit sheet.

### The fix

```html
<meta name="viewport" content="width=device-width, initial-scale=1.0, viewport-fit=cover">
```

One attribute. Then confirm the note edit sheet gets a bottom safe-area pad — check `NotesView.jsx` around the sheet style (`~822`); it currently has no `paddingBottom: env(safe-area-inset-bottom)` of its own, unlike the filter sheet which does.

### NS check

Shell-level and corrective — NS lists safe-area insets as a shipped mobile feature; this makes them actually work. No visual-system conflict. Do NOT add `maximum-scale` / `user-scalable=no` — that would disable pinch-zoom and violate NS Evolution (accessibility/font-scaling is protected). This fix is independent of W3 (the input-zoom font change, which is v0.98.7).

### Constraints

- Only the viewport meta + the edit-sheet bottom pad. Don't touch other safe-area call sites — they already pad correctly and will simply start resolving to non-zero.

### Verification

1. Notched iPhone, installed to home screen (standalone): TopBar clears the status bar/notch; content not under it.
2. Home indicator does not overlap the footer transport.
3. Open the note edit sheet: its bottom (and the keyboard-lift behavior) clears the home indicator.
4. Non-notched device and desktop: no regression (env insets resolve to 0 as before, layout unchanged).

## Fix 2 — Shared wiki-link rendering fix (W2/W8)

### Why

The journal's connective tissue must be nearly perfect, and v0.98.7 converts four more surfaces to the shared markdown renderer — so fixing the shared component now means those conversions inherit correct behavior for free. Two breaks in `MarkdownComponents` (`shared.jsx:497-537`):

- **Dead links look live.** When `completionData` is not threaded, `resolveWikiLink` is never consulted, so every `[[link]]` — even to a non-existent target — renders as a live blue clickable link. The log-entry read site omits it (`RepertoireView.jsx:603`).
- **Live `wikilink://` anchor is an iOS hazard.** The shared path renders a real `<a href="wikilink://…">` and relies on an `onTouchStart` `preventDefault` to stop iOS navigating the unknown scheme. Mobile NotesView deliberately avoided this by rendering a `<span>` (`NotesView.jsx:886`, with an explanatory comment) — but it was never back-ported.

### The fix

In `shared.jsx` `MarkdownComponents`:

- Thread `completionData` through so `resolveWikiLink` is consulted. An unresolved `[[link]]` renders **dimmed and non-clickable** — a muted/faint tone, **not IKB** (NS: IKB only where it means something; a dead link means nothing). A resolved link renders as a live link and navigates.
- Render wiki targets as a **`<span>`** (or `href="#"`) rather than a live `<a href="wikilink://">`, matching the NotesView hardening — no unknown scheme for iOS to chase.

At the log-entry read site, pass `completionData={wikiCompletionData}` to the read-only `MarkdownField` (`RepertoireView.jsx:603`).

### NS check

Dimming unresolved links off IKB is NS-aligned (corrective, not a new color). The `<span>` change is invisible to sighted desktop users; it removes an iOS failure mode.

### Constraints

- Don't diverge from the existing `resolveWikiLink` contract or the `wikiUrlTransform` whitelist behavior used elsewhere.
- Keep the desktop render visually identical for *resolved* links (same IKB link styling); only *unresolved* links change (now dimmed) and the anchor element changes to span.
- This touches the shared component used by Repertoire pinned notes, log entries, and the reflection read paths — verify each still renders.

### Verification

1. Type `[[NonexistentThing]]` in a pinned note → renders dimmed, not clickable, not IKB.
2. Type `[[<real piece>]]` → renders as a live link; clicking navigates to the piece.
3. Log entry with a valid `[[link]]` → now resolves correctly (previously rendered live regardless).
4. iPhone Safari: tap a wiki-link in a read view → navigates in-app; the browser never attempts a `wikilink://` scheme load.
5. No regression on the surfaces that already worked (NotesView desktop/mobile, LogDrawer).

## Fix 1 — Real persistence + honest autosave indicator (W1)

The largest and most important fix. Decided shape (plan C): **per-note keys now; IndexedDB fallback deferred to v0.99.x.** Three parts: stop the catastrophic loss (per-note keys + non-global failure), make `lsSet` honest (returns false), and surface the truth (indicator driven by real write results).

### The real problem (not just the fake label)

`etudes-freeNotes` holds the entire notes array as one JSON string (`useEtudesState.js:101`). `lsSet` (`storage.js:12`):

```js
export function lsSet(k,v){
  if(!storageAvailable){memStore[k]=v;return true;}
  try{ localStorage.setItem(k,JSON.stringify(v)); return true; }
  catch{ storageAvailable=false; memStore[k]=v; try{window.dispatchEvent(new CustomEvent('etudes-storage-full'));}catch{} return true; }
}
```

Three faults: (a) one big note pushes the whole `etudes-freeNotes` blob over quota; (b) the first failure sets `storageAvailable=false` **globally**, so every subsequent write to *any* surface goes to memory only; (c) it returns `true` on failure, so callers can't react. The note is lost on reload, silently.

### Part A — Per-note keys (stops the catastrophic loss)

Split free notes from one blob into one key per note, so a single oversized note can only fail its own write, not the journal.

- **Storage layout:** each note persists under `etudes-note-<id>`; an index key `etudes-note-index` holds the ordered list of note ids (for enumeration and order). Reflections (`etudes-dailyReflection`, etc.) and `etudes-items` stay single-blob in this release — free notes are the unbounded-growth surface and the worst offender; the rest are covered by Parts B/C now and the IDB escalation later.
- **One-time migration on load:** if the legacy `etudes-freeNotes` blob exists, split it into per-note keys + index, then mark it migrated (e.g. remove the legacy key only after the per-note writes succeed, or set a `etudes-notes-layout=2` marker). This is a **storage-layout migration**, distinct from SCHEMA_VERSION (which is about state *shape*). Decide with the implementing agent whether it rides the v11 migration or uses its own marker — leaning toward its own marker since SCHEMA_VERSION operates on the loaded state object, not the persistence layout. **Open question, flagged.**
- The notes loader (`useEtudesState.js` init, ~line 71) reads the index then each note key; the persist effect writes only the changed note's key (not the whole array) — this is also a real write-amplification win.

### Part B — `lsSet` returns false, and stop the global disable

```js
export function lsSet(k,v){
  try{
    localStorage.setItem(k,JSON.stringify(v));
    emitWriteResult(k,true);
    return true;
  }catch(e){
    memStore[k]=v;                                  // keep in memory so the session isn't broken
    try{window.dispatchEvent(new CustomEvent('etudes-storage-full'));}catch{} // keep Sync WARN (v0.98.2)
    emitWriteResult(k,false,'quota');
    return false;                                   // callers can now react
  }
}
```

Key behavior change: **do not set `storageAvailable=false` permanently on one failure.** A transient quota spike on one big write should not doom every small subsequent write to memory. Each write attempts independently. (If `storageAvailable` is read elsewhere as a short-circuit, reconsider those call sites — the implementing agent should audit uses of `storageAvailable`/`memStore`. **Flagged.**)

### Part C — Honest indicator, driven by real write results

Same event/component design as the Jun-8 draft, but with the **corrected camelCase keys** and driven by real success/failure:

```js
const WRITING_SURFACE_KEYS=new Set([
  'etudes-freeNotes',        // legacy blob (pre-migration reads)
  'etudes-dailyReflection',
  'etudes-weekReflection',
  'etudes-monthReflection',
  'etudes-items',            // holds item.detail, item.todayNote, item.noteLog, spots
  'etudes-programs',
]);
function emitWriteResult(key,ok,reason){
  // match the writing-surface keys AND the per-note keys
  if(!WRITING_SURFACE_KEYS.has(key) && !key.startsWith('etudes-note-'))return;
  try{ window.dispatchEvent(new CustomEvent('etudes-write-result',{detail:{key,ok,reason,t:Date.now()}})); }catch{}
}
```

> **Bug fixed from the Jun-8 draft:** the old allowlist used `etudes-free-notes` / `etudes-daily-reflection` (kebab-case) — the real keys are camelCase, so the old allowlist matched nothing and the indicator would never fire.

`useEtudesState` listener (`saveStatus` state) and the `SaveIndicator` component are as the Jun-8 draft specified (idle / saved-fades-1.5s / failed-sticks-until-next-success), with NS voice ("Storage full" / "Save failed", uppercase letterspaced, WARN tone for failure). Wire it into the TodayMobile reflection eyebrow, **replacing** the fake `'Saved'/'Empty'` label (`TodayView.jsx:892-894`), filtered to `s.key==='etudes-dailyReflection'`.

```jsx
// After:
<SaveIndicator saveStatus={p.saveStatus} filter={(s)=>s.key==='etudes-dailyReflection'}/>
```

For v0.98.6, the indicator surfaces on the **TodayMobile reflection only** (most visible offender). Other surfaces can grow indicators later; don't add one next to every MarkdownField (noise).

### Deferred (plan C escalation — NOT this release)

IndexedDB fallback for note/reflection bodies (kills the 5 MB ceiling entirely) is the v0.99.x escalation. Trigger to pull it forward: device testing shows a real founding-cohort user's *total* notes exceed the localStorage ceiling even with per-note keys. Note it in the v0.99.x candidates.

### Constraints

- Per-note migration must be idempotent and lossless — never drop a note if a per-note write fails mid-migration (keep the legacy blob until all per-note writes confirm).
- Don't change the existing `etudes-storage-full` event flow — the Sync tab WARN (v0.98.2) depends on it.
- The "failed" indicator state sticks until the next successful write; don't auto-fade errors.
- `SaveIndicator` returns null when idle — no empty `<span>` causing layout shift.
- Don't fire `etudes-write-result` for non-writing-surface keys.

### Verification

1. **iPhone, normal:** expand reflection, type → "Saved" appears briefly and fades. Type fast → settles after debounce.
2. **iPhone, near quota** (fill localStorage via Mac Safari inspector): type in the reflection → "Storage full" appears and **sticks**. Clear quota, type → recovers to "Saved" → idle.
3. **Per-note keys data integrity:** create several notes → verify each persists under `etudes-note-<id>` and `etudes-note-index` lists them in order. Reload → all notes present, order preserved.
4. **Migration:** load a pre-v0.98.6 state with notes in the legacy `etudes-freeNotes` blob → on open, notes split into per-note keys, legacy key cleared/marked, no notes lost. Run on: fresh state, state with notes, state with no notes.
5. **Catastrophic-loss gone:** create one very large note near quota → its write fails (indicator shows it), but other notes and reflections still save (no global memory-only flip). Reload → the small writes persisted.
6. **Sync regression:** the Sync tab storage-quota WARN still appears on quota error.

## Fix 4 — Notes `updatedAt` field

*(unchanged in intent from the Jun-8 draft; coordinate its v11 migration with Fix 1's per-note layout)*

### The fix

Add `updatedAt` to notes, write on every mutation, migrate existing notes, optionally use in `mergeStates`.

- **Migration (schema v11):** `migrateTo11(state)` sets `updatedAt: n.updatedAt||n.date||Date.now()` for each note. Append as version 11, register like `migrateTo10`. Bump `SCHEMA_VERSION=11` in `src/constants/config.js`.
- **Write on mutation:** in the canonical `updateNote(id,patch)` and `addNote`, set `updatedAt: Date.now()` (addNote initial = `date`). Audit other `freeNotes` write sites; import flow preserves existing `updatedAt` else `n.date||Date.now()`.
- **`mergeStates` last-write-wins (optional, deferable):** prefer larger `updatedAt` for same-id note conflicts only; don't change default local-wins for other fields. Defer to v0.99.x if complex.

### Coordination with Fix 1

Fix 1 changes how notes are *persisted* (per-note keys); Fix 4 changes their *shape* (adds `updatedAt`). Sequence them so the v11 state migration (shape) and the storage-layout migration (per-note keys) compose cleanly on load — run the shape migration on the loaded state, then persist out to the new per-note layout. Do not let one silently undo the other. **Flag in the PR.**

### Constraints

- `structurallyEqual` (sync.js) must ignore `updatedAt` differences, else every post-edit sync reads as a conflict. Add `updatedAt` to its ignore list.
- Never update `n.date` on edits (creation, immutable).
- Migration idempotent; existing notes get `updatedAt = n.date`.

### Verification

1. Fresh state: create note, edit body → `updatedAt` updates.
2. Pre-migration state → migration adds `updatedAt = n.date`; `etudes-schema-version` becomes `'11'`.
3. Sync: two browsers, edit same note at different times, force sync → no false conflict (structurallyEqual ignores updatedAt).
4. Genuine conflict (different body on two devices) → modal still appears.
5. vitest: existing `sync.test.js` passes; add a test that `structurallyEqual` ignores `updatedAt`.

## Surprise budget

- **`storageAvailable` global flag has other readers.** Removing the permanent global-disable (Fix 1 Part B) may affect call sites that read `storageAvailable` as a short-circuit. Audit them; preserve correctness (the goal is per-write independence, not removing the in-memory fallback).
- **Per-note migration ordering vs schema v11.** Two migrations touch notes (shape: updatedAt; layout: per-note keys). Compose them deliberately on load (shape first, then persist to new layout). Test the pre-v0.98.6 path hardest.
- **`etudes-items` is one key.** The SaveIndicator keyed to `etudes-dailyReflection` is unaffected, but note that `etudes-items` writes fire on practice-time/BPM/performance changes too — keep the reflection indicator scoped to its own key, not items.
- **SCHEMA_VERSION may not be 10.** Verify `grep SCHEMA_VERSION src/constants/config.js`; use the next integer if the trilogy bumped it.
