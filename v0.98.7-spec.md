# v0.98.7 — Writing-surface markdown

> **Drafted 2026-06-13**, grounded in the current `main` *after* v0.98.6 shipped (line numbers verified post-0.98.6). Derives from [[Writing-Surfaces_2026-06-08]] (W3, W5, W6) and [[Gate-A-Writing-Surfaces_2026-06-10]]; sequenced by [[Roadmap v0.99.1]]. Authority: `North_Star_V2.5.md` (repo) — referenced as NS with section names, since vault headings avoid the section glyph.

The second Gate A release. v0.98.6 made the journal *trustworthy*; v0.98.7 makes the remaining writing surfaces *first-class* — every place NS calls reading-prose becomes a real markdown plus wiki-link surface, at one consistent fidelity. Per NS Style, "journal reflections, intentions, note bodies, spot annotations, program body text" are all EB-Garamond reading prose; four of them are still plain `<textarea>`. This release closes that gap.

Three fixes:

1. **W5 — convert the Tier-2 plain `<textarea>` surfaces to `MarkdownField`/`MarkdownEditor`** with full wiki support: spot note, log-entry add and edit, program intention, program reflection, and the PdfDrawer `todayNote`/`detail` editors. They already *store* markdown; now they render and edit it, with `[[ ]]` autocomplete and clickable resolution.
2. **W6 — fix program-body wiki-links** (autocomplete props missing; bespoke renderer with a narrowed resolver) by unifying the program body onto the shared markdown components.
3. **W3 — 16px reading-prose editor font on mobile**, set once in the shared `MarkdownField`/`MarkdownEditor` so every surface (existing and newly-converted) inherits it and iOS stops zoom-on-focus.

Build order: **W3 + the shared wiki-wiring foundation first** (so the conversions inherit correct font and rendering), then the per-surface conversions, then the program-body unification. One commit per fix on the same branch.

No schema change, no storage-layout change. This is a UI-fidelity release — lower risk than v0.98.6, but it touches many surfaces, so the discipline is consistency and behavior-preservation (lock logic, save models).

---

## Why this release exists

The journal's connective tissue and its prose are the product. Today a musician writing a spot annotation, a program intention, or a session log gets a bare textarea — no markdown, no `[[ ]]` autocomplete, links typed there render as literal text. The same thought typed into a free note is a rich, linked surface. That inconsistency is exactly what NS Style forbids ("one coherent aesthetic") and what the Gate A bar ("all writing surfaces functional per NS") closes. v0.98.6 already hardened the shared renderer; this release routes the last surfaces through it.

## Foundation (build first)

### W3 — 16px reading-prose editor font on mobile

**Current:** the shared editor defaults to 15px in both modes — `MarkdownEditor.jsx:252` (`fontSize='15px'` default param, fed to `buildBaseTheme`) and `MarkdownField` (`shared.jsx:546` read-only render, `:565` editor). iOS Safari zooms on focus for any editable below 16px, so every prose surface zoom-jumps on iPhone.

**Fix:** make the shared default **16px on mobile, 15px on desktop**, inside `MarkdownField`/`MarkdownEditor` (read `useViewport().isMobile`). NS Style endorses 15-16px for EB Garamond, so 16px is in range. Every W5-converted surface inherits this for free; NotesView already passes 16px explicitly and is unaffected.

**Method, non-negotiable (NS Evolution):** font-size only. Do **not** add `maximum-scale`/`user-scalable=no` — that disables pinch-zoom and violates the accessibility protection. Desktop stays 15px byte-for-byte (mobile-conditional in the `else` branch).

### Wiki-wiring helper

Every converted surface needs the same two things threaded in: `onWikiLinkClick={handleWikiLinkClick}` (the global handler from `App.jsx`, which already resolves and navigates *all* target types) and `completionData={wikiCompletionData}` (so the shared `MarkdownComponents` — hardened in v0.98.6 — resolves links, dims dead ones to FAINT, and renders the rest as IKB `<span>`s). Two target components do not currently receive these props and must be threaded: **`SpotEditor`** and **`PdfDrawer`** (both in their render trees from `RepertoireView`/the lazy `PdfDrawer`). Confirm the prop path before converting.

## W5 — Tier-2 surface conversions

All six follow the same shape: replace `<textarea>` with `MarkdownField` (or `MarkdownEditor` for a compose box), thread `onWikiLinkClick` + `completionData`, preserve the surface's save model and any gate. Per-surface specifics:

| # | Surface | Site (current) | Save model now | After |
|---|---------|----------------|----------------|-------|
| 1 | Spot note | `RepertoireView.jsx:66` (`SpotEditor`, `<textarea value={note}>` serifText 12px) | local state + commit on blur (`cN`) | `MarkdownField value={spot.note||''} onChange={v=>onUpdate({note:v})}` — on-change, drops the blur-commit (also fixes the blur-data-loss risk, audit W22). Thread wiki props into `SpotEditor`. |
| 2 | Log-entry add | `RepertoireView.jsx:521` (`<textarea value={newNoteText}>`) | compose box + explicit **Save** button (`handleAdd`) | `MarkdownField value={newNoteText} onChange={setNewNoteText}` — keep the Save/Cancel buttons and `handleAdd`. Compose model preserved; gains markdown + `[[ ]]` autocomplete. |
| 3 | Log-entry edit | `RepertoireView.jsx:588` (`LogEntry` edit-mode `<textarea>`) | local `text` + commit on blur/Save (Escape reverts) | `MarkdownField` with the same commit-on-blur/Save. Display already uses `MarkdownField readOnly` (v0.98.6 added `completionData`); this makes editing match. |
| 4 | Program intention | `ProgramsView.jsx:202` (`<textarea>`), gated by `intentionReadOnly` | on-change `update({intention:v\|\|null})` + on-blur trim; **locked** branch (`:192-200`) shows pre-wrap raw text + "Locked after performance date." | Editable → `MarkdownField onChange={v=>update({intention:v\|\|null})}`. **Locked → `MarkdownField readOnly`** (renders the markdown instead of raw text) + keep the "Locked after performance date." note. Preserve the `intentionReadOnly` gate exactly. |
| 5 | Program reflection | `ProgramsView.jsx:319` (`<textarea>`), gated by `isFuture` | on-change + on-blur trim; **future** branch shows "—" | Future → keep "—". Else → `MarkdownField onChange={v=>update({reflection:v\|\|null})}`. Preserve the `isFuture` gate. |
| 6 | PdfDrawer todayNote + detail | `PdfDrawer.jsx:523` (`todayNote`), `:613` (`detail`) | on-change `updateItem` | `MarkdownField` for both, matching their TodayView/Repertoire counterparts (which are already `MarkdownField`). Thread wiki props into `PdfDrawer`. Closes the audit's todayNote parity gap (W8/W13). |

**Save-model note for the agent.** Converting on-blur surfaces (spot note, intention, reflection) to `MarkdownField`'s on-change persistence is intentional and an improvement — it removes the unmount-without-blur data-loss path. But the on-blur `trim()`-to-null on intention/reflection is lost; do **not** trim on every keystroke (it would strip a trailing space mid-typing). Acceptable to persist `value||null` on change and drop the trim, or apply the trim only when the editor blurs if `MarkdownField` exposes a blur hook. Flag whichever you choose.

**Not in scope:** the per-piece annotation `<input>` (`ProgramsView.jsx:251`) and program `name`/free-note `title` stay plain single-line inputs — NS treats them as metadata, not prose (audit "secondary plain fields").

## W6 — Program-body wiki-links

The program body is **not** on the shared renderer — it has a bespoke `wiki://`-scheme implementation (`ProgramsView.jsx:339-356` preview, `handleBodyWikiClick`), and the editor (`:362`) is missing its completion props. Two concrete defects from the audit:

- **Autocomplete dead:** `MarkdownEditor` at `:362` is called without `items/history/programs/notes`, so `[[` offers nothing.
- **Resolver narrowed + click handler partial:** the preview resolves with `resolveWikiLink(raw,items,[],null,freeNotes||[])` (`:347`) — `history=[]`, `programs=null` — so day and other-program links can never resolve, and `handleBodyWikiClick` only navigates `type:'note'`, so item/spot links render live but are dead on click.

**Fix — unify onto the shared components** rather than patch the bespoke path:

- **Editor:** add `items={items} history={history} programs={programs} notes={freeNotes}` to the `MarkdownEditor` at `:362` (autocomplete) — or, if simpler, route through `MarkdownField` like the other surfaces.
- **Preview:** replace the inline `ReactMarkdown` + custom `a` renderer (`:339-356`) with the shared **`MarkdownField readOnly`** wired to `onWikiLinkClick={handleWikiLinkClick}` (the global App.jsx handler, which navigates all types) and `completionData={wikiCompletionData}`. This inherits the v0.98.6 hardening: full resolution (item/spot/program/note — day too where applicable), dead links dimmed to FAINT, `<span>` not `wikilink://` anchor. Retire `handleBodyWikiClick` and the local `wiki://` rewrite once the shared path covers it.

NS check: this *removes* a second wiki scheme and a second renderer — consistent with NS Style ("one coherent aesthetic; do not invent new ones") and Evolution ("prefer removal to rearrangement").

## Constraints (NS-derived)

- **Wiki support on every converted surface:** thread `onWikiLinkClick={handleWikiLinkClick}` (global) + `completionData={wikiCompletionData}`. Surfaces that don't currently receive them (`SpotEditor`, `PdfDrawer`) get the props threaded down.
- **W3 method:** font-size on mobile only; never disable pinch-zoom (NS Evolution).
- **Tokens:** no hardcoded color/font — import from `src/constants/`. Unresolved links render FAINT, never IKB (the shared component already does this; converted surfaces inherit it).
- **Preserve gates and save models exactly:** `intentionReadOnly` (locked-after-performance) and `isFuture` (reflection) must behave identically; the log-add compose/Save flow stays.
- **Mobile conditionals preserve the desktop code path BYTE-FOR-BYTE** in the `else` branch (NS Evolution).
- **No z-index changes** (UpdatePrompt z-stack is v0.99.1). No storage/schema changes. No `updatedAt` work (notes-only, shipped in v0.98.6; spot/log/program records are out of scope for timestamps).
- **Voice:** any new copy quiet, declarative, no exclaim/apologize/emoji.

## Verification

Per converted surface (desktop + iPhone): type `**bold**`, a `# heading`, and `[[<real piece>]]` plus `[[Nonexistent]]` →

1. Markdown renders (not literal); `[[` opens autocomplete; the real link resolves and navigates on click; the dead link is FAINT and inert.
2. **iPhone:** focusing the editor does **not** zoom the page (16px). Caret stays put.
3. **Lock logic:** a program with a past performance date shows intention **read-only as rendered markdown** + "Locked after performance date."; a future program shows reflection "—". Editable states still save.
4. **Save:** edit a spot note, navigate away without an explicit blur (e.g. switch pieces / hard reload) → the edit persisted (on-change). Log add still requires Save; Cancel discards.
5. **Program body:** `[[piece]]`, `[[spot #x]]`, `[[note]]`, `[[program]]` all resolve and navigate; autocomplete offers them; preview/edit toggle works.
6. **No regression** on the surfaces already markdown (free notes, reflections, pinned notes) — they should look identical except 16px on mobile.

`npm test` (existing suite stays green; no new pure helpers expected — add one only if you extract logic), `npm run build`, `npm run lint` (expect net-zero or near; flag any new rule category). Real-device iOS for the zoom check and the wiki taps.
