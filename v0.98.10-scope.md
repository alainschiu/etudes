## 0. The gate — decide this first

**Question (Alain, from practice notes):** now that spot→page links, bookmark notes, and readable export are in daily use, is a light mark layer still make-or-break — or do links + notes cover the need?

- **Build** → v0.98.10 "Marking" (this scope), then v0.99.0.
- **Cut** → straight to v0.99.0; marking becomes a v1.x candidate. Costs nothing already built; **frees the slot before the late-August beta.**

**Architect read:** the *code* is ready for it (the anchor, storage, Drive, and export hooks all exist — §1), and the *data* side is genuinely light. The risk is **not** the model; it's whether the **input layer feels right on iOS** (Pencil/finger/palm/scroll-vs-draw). That risk is real enough that the build itself is **prototype-gated** (§2, build order): the first ~2–3 days build only the input layer on a real iPad + Pencil, and if it can't be made to feel good, marking is cut *then*, with nothing wasted. So the gate has two stages: **Alain's need-call now**, then **an input-quality prototype-call during the build.**

**Recommendation:** if your practice notes still say "I mark passages, every session, and I'm not doing it in Études" — build, but accept the prototype as a real kill-switch. If links+notes have quietly covered it — cut, bank the schedule, revisit post-launch.

## 2. Scope if built (light — highlight + ink, undo, no eraser v1)

### Data model
```
mark   = { id, type:'ink'|'highlight', color, w, ...geometry, t }
  ink       → points: [[x,y], …]         (normalized 0–1 of the page box; w = stroke width normalized to page width)
  highlight → rect:   {x,y,w,h}          (normalized 0–1)
pageMarks = { v:1, strokes: [mark, …] }
```
- **Key: `${libraryId}::${absolutePage}` (C5, C2).** Not attachment, not item — one PDF shared across pieces means a fingering circled while practicing Piece A shows when Piece B opens the same score. Overlay reads by the *active attachment's* `libraryId` + page.
- **Normalized coordinates (C2-aligned):** 0–1 of the PDF page box — zoom-, fit-, and device-independent. Never render-pixels, never range-relative.

### Rendering — SVG overlay
- One `<svg viewBox="0 0 1000 1000" preserveAspectRatio="none">` absolutely positioned at `inset:0` inside each page's C7 wrapper; strokes scale with the wrapper automatically (no re-layout on zoom/fit).
- `highlight` → `<rect>` with a translucent fill (multiply-ish); `ink` → `<path>`/`<polyline>`.
- Read-only first (M2): load `pageMarks` by key, draw. Works in single/spread/continuous (the wrapper is per-page in all three).

### Input layer — **the risk; prototype this first**
- Overlay is `pointer-events:none` (pass-through: normal scroll/zoom) **until a tool is active**; then it captures pointer events with `touch-action:none` so a stroke never scrolls the page. **Mode-based**, unambiguous — the standard light-annotator model.
- `pointerdown/move/up`; `getCoalescedEvents()` for smooth ink; `clientX/Y → normalized` via the wrapper's `getBoundingClientRect()`.
- **`pointerType`:** `'pen'` always draws. **Decision (Alain):** finger draws when a tool is active (simplest, recommended) vs Pencil-only. Palm rejection handled cheaply by (a) tool-active gating — you opt in — and (b) tracking only the first active pointer (ignore secondary touches).
- **Decision (Alain):** marking in **continuous** mode — enable, or restrict to single/spread + fullscreen (recommended: single/spread/fullscreen only; drawing while a long scroll is live is awkward and the memory-heavier mode is where you least want it).

### Persistence
- Save on **stroke-end** (`pointerup`) → write `pageMarks` to IDB `marks` via `idbPut`, honoring the **false return** (F4 pattern): on failure, quiet NS-voice line — *"Could not save marks on this device."* — and keep the stroke in memory for the session.
- **Undo:** in-memory per-page stroke stack; undo pops the last stroke and rewrites the page's store entry. No eraser in v1.
- **`navigator.storage.persist()`** already requested at boot (F4) — marks inherit the durability.

### Drive backup + export (C4 — device-local + Drive, **never Supabase**)
- **Backup:** add a `marks` namespace to `driveBlobRefs` by enumerating `idbAllKeys('marks')`; each `pageMarks` serializes to a small JSON `Blob` and rides the **existing** `driveSync` upload/download + F4b honest-restore verbatim. `driveManifest` gains one additive field if needed (its forward-compatible policy).
- **Supabase stays clean by construction:** marks live only in IDB, never in `coldState`, so the Supabase JSON payload never grows (C4, and it keeps us clear of the 500 KB sync warning — cascade risk R7).
- **Export:** marks in `_data.json` as `marks:{ "libId::page": pageMarks }` (small, re-importable); `applyJournalPayload` writes them to IDB on import (with `{failed}` honesty). **Human-readable burn-in** (marks flattened into PDF copies) is **out of scope** — flagged for the print/PDF track.

### Color — **NS-level decision (Alain)**
Palette today: IKB (active/practice), WARM `#B89668` (rest/warm-up/locked), ivory/ink neutrals. Neither fits a mark:
- **A — reuse WARM at low opacity.** No new token, "within vocabulary." But gold ink reads oddly as pencil, and WARM already means rest/locked — overloading it muddies the token.
- **B — add a `GRAPHITE` material token (recommended).** A mark is genuinely its own material (pencil/graphite on paper); forcing it into IKB or WARM misuses both. One new token for ink (a soft graphite), a translucent tint for highlight. It's an NS Evolution call, made deliberately — not defaulted.
- **Recommendation: B (graphite).** Cleanest semantically; the spare palette stays meaningful. Alain's call before build.

### Tests
- Pure helpers (vitest): `client↔normalized` round-trip; `pageMarks` (de)serialize; the `(libraryId,page)` key builder. Input/gesture quality = **device-only** (Playwright + real iPad/Pencil).

### Build order (prototype-gated)
0. **PROTOTYPE (throwaway if it fails)** — input layer on the overlay: pen + finger, mode gating, coalesced smoothing — on a **real iPad + Pencil**. *This is the kill-switch.*
1. **M1** — IDB v4 `marks` store + storage helpers + honest failure.
2. **M2** — read-only SVG overlay (load & draw by key; single/spread/continuous).
3. **M3** — input + tools (highlight, ink, undo) wired to save.
4. **M4** — Drive backup (`driveBlobRefs` + restore) + export/import (`_data.json`).
5. **M5** — graphite token + toolbar/C6 polish + version bump + CHANGELOG.

### Risk parity
| Surface | Effect |
|---|---|
| **SCHEMA_VERSION** | **UNCHANGED (12)** — marks are IDB-only, never in synced state |
| IndexedDB | `openDB` **v3 → v4** (its own versioning; add `marks` store) |
| Supabase payload | **unchanged** (C4 — marks never enter `coldState`) |
| Drive | +`marks` in blob backup/restore; manifest additive |
| Tests | +helpers; input is device-verified |
| Build | new `MarkOverlay` + tool state; no new deps (SVG + Pointer Events are native) |
| The real risk | **iOS input feel** — mitigated by the prototype gate, not by code review |
