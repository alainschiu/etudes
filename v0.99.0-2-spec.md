## Part 0 — Shared conventions (the cross-release contract)

**C1. Error copy is mapped, never raw.** One pure helper (`mapSyncError(e)` in a small lib) translates every auth/sync failure to NS voice: network-unreachable → "Could not reach the sync service. Your data is safe on this device."; bad credentials → "Email or password did not match."; unconfirmed email, rate-limit → their own quiet lines; unknown → a generic quiet line. No raw `error.message` from Supabase or fetch ever reaches a writing surface. Drive already has `formatDriveError` — align its voice, don't fork the pattern.

**C2. The journal payload has two modes, and the Drive journal is metadata-only forever after.** `buildFullJournalPayload(slice, lsGet, {blobMode})`: `'none'` omits the `blobs` key entirely (no IDB enumeration); `'embedded'` is unchanged. Drive journal push and pull-compare use `'none'`; file export/import keeps `'embedded'`. Compatibility is asymmetric by design: the app must still *read* old Drive journals that carry embedded blobs (parse tolerant; restore continues to take blobs from the per-file Drive folders, as it already does via `blobMode:'none'` apply + `restoreBlobsFromDrive`).

**C3. All merge logic lives in `mergeStates` — one shared implementation.** The Supabase conflict path and any future Drive merge call the same function. Merge outcome is **deterministic and device-independent**: same two states → same result, regardless of which device runs it. No feature may fork a private merge.

**C4. Timestamp semantics.** `updatedAt` = epoch ms, stamped **only on user-initiated mutation** — never during migration, merge, or cloud-apply (guard with the existing `applyingCloudRef` pattern; a stamp war where applying remote state re-stamps everything newer defeats LWW). Missing/0 `updatedAt` always loses to a stamped one; two missing → current behavior (local wins) so unstamped legacy data degrades gracefully.

**C5. Schema v13 is one bump, in v0.99.2 only.** Everything that changes persisted shape (entity stamps, reflection sidecar, settings stamp, tombstones) rides the single v13 migration — unconditional idempotent live-load migrators (house pattern) + `IMPORT_MIGRATIONS {from:12, to:13}`. v0.99.0 and v0.99.1 must not touch persisted shape. (The Drive manifest is not under SCHEMA_VERSION — its additive-field policy covers v0.99.1's needs.)

**C6. Drive token continuity model.** Boot attempts **one silent renewal** when the device-local connected marker is set (per A2) — quiet failure, never a popup, never a nag. Token presence becomes **reactive state** (a `driveReady` boolean in `useDriveSync`, updated on connect/renew/disconnect), replacing non-reactive `hasDriveToken()` gating in effects — this is the root cause of the dead-interval wart and must be fixed as state, not patched with re-checks. Interactive reconnect drops `prompt:'consent'` (default prompt; Google shows consent only when it must). The UI never claims auto-backup is running without a live token: token-dead-but-connected renders an honest "Backup paused since last app start" line with a one-tap resume.

**C7. iOS gesture invariants stand (repo CLAUDE.md).** No `await` between user gesture and popup; `prepareDriveAuth()` eager at boot; the GIS `<link rel="preload">` stays; silent renewal at boot is safe (no popup on the silent path). Nothing in this run may reorder that chain.

**C8. Verification floor.** Per release: `npm test` / `npm run build` / `npm run lint` (baselines 57 / 170) + new tests for every new pure helper (error map, payload modes, LWW comparator, tombstone merge, inventory summary). Real-iPhone pass for anything touching Drive/auth/mobile surfaces. v0.99.2 additionally runs the **two-device conflict matrix** (Part 3) on Mac + iPhone before merge.

Deviating from Part 0 requires the architect, not a workaround.

## Part 1 — v0.99.0 "Sync honesty + operational"

No schema change. One commit per fix.

**F1 — Error mapping (audit T3a).** Implement C1's `mapSyncError` + unit tests; apply in the Sync tab auth form (sign-in, sign-up, reset paths) and wherever sync status errors surface. Observed live: unreachable backend leaked raw "Failed to fetch"; wrong password leaked raw "Invalid login credentials".

**F2 — OAuth redirect guard (T3b).** `signInWithGoogle` currently navigates the whole tab to the Supabase authorize URL unconditionally (`useSupabaseAuth.js:33`) — if the backend is unreachable the user is stranded outside the app. Fix: probe reachability first (fetch `auth/v1/health` with a ~4s `AbortSignal.timeout`; any HTTP response = reachable, only network failure throws) → on failure, in-app C1 line, no navigation. Happy-path cost ~100ms.

**F3 — Timer practice syncs (T5).** `itemTimes`/`restToday` are excluded from the dirty-marker (`useEtudesState.js:132`) and the auto-sync debounce (`:678`) — a timer-only session never syncs. **Do NOT naively add them to the effect deps** — `itemTimes` mutates every second while the timer runs; per-tick dirty would sync continuously during practice. Correct design: mark dirty + nudge the sync debounce at the **natural boundaries** — `stopItem`, `toggleRest` (off), `editItemTime`, `editSpotTime`, day close/reopen. A practice session then syncs when it pauses or ends, not while it runs. **Extended by A5.**

**F4 — Storage-line actionability (T8).** The signed-out Sync tab says "Back up to Drive." while Drive controls are invisible (they live in the signed-in branch). Branch the action clause on state: signed-out → "Back up with Export, or sign in to enable Drive backup."; signed-in states keep current copy.

**F5 — UX batch (audit workflow section; one commit, mechanical).**
- Backup/restore naming, interim per Q7a (recorded as temporary; destination = the unified Data surface, v0.99.5+ band): Export tab → "Back up to file" / "Restore from file"; Sync tab → "Back up to Drive" / "Restore from Drive".
- File-backup feedback: quiet italic line after the download/share fires — "Backup saved." (voice-check against existing status lines).
- `ConfirmModal` gains an `ackOnly` prop (renders OK only); apply to "Backup restored successfully.", "Restored from Google Drive.", "No journal on Google Drive yet."
- Restore-inventory date renders **local** (`toLocaleDateString`-class), not the UTC ISO substring — kills the HKT off-by-one.
- Create-account mode header: "Create account with email" (currently stays "Sign in with email").

**Alongside (infra, not in the PR):** the Supabase keep-alive loop — a weekly scheduled task (Loops registry, loop-engineer lane) doing an authenticated PostgREST `select 1`-class read; failure alerts. Doubles as uptime monitoring (audit O2). Move to paid plan at beta invitations (decision 2026-07-12).

**v0.99.0 verification:** unreachable-backend sign-in shows the C1 line in-app (dev: point env at a dead URL); wrong password shows the mapped line; GOOGLE with backend down stays in-app; timer-only session → close tab → other device sees the time after its next pull; all five UX items visually verified on iPhone + desktop.

## Part 2 — v0.99.1 "Drive backup continuity"

No schema change. One commit per fix. Requires a `VITE_GOOGLE_CLIENT_ID` build for device verification.

**F1 — Metadata-only journal push (T1).** Implement C2. `pushToDrive` builds `blobMode:'none'` (`driveSync.js:188`); the journal file drops from potentially hundreds of MB (base64 media) to KBs; pull-compare stops downloading the library. Export/import unchanged (`'embedded'`). Tolerant read of legacy embedded journals per C2. **Ships with A1's blob-coverage escalation — hard prerequisite.**

**F2 — Skip-unchanged blob uploads (T6).** Full-mode push re-uploads every blob every time (`driveSync.js:202-239`). **Per-store policy per A3** (replaces uniform size-compare).

**F3 — Boot silent renewal + reactive token (T2).** Implement C6 as amended by A2 (device-local marker) and A4 (timeout wrapper): on boot, marker set → after `prepareDriveAuth()`, silent renewal quiet-catch; introduce `driveReady` state in `useDriveSync` consumed by the auto-backup interval effect, `notifyBlobWrite`, and the Sync-tab render (replacing non-reactive `hasDriveToken()` reads in those paths). Honest paused-state line + one-tap resume when renewal fails (ITP reality — if device testing shows silent renewal rarely works on iOS Safari, the paused-line-plus-one-tap IS the shipped behavior, and that is acceptable — what may not ship is the silent lie).

**F4 — Reconnect without forced consent (T2b).** `requestDriveTokenInteractive` drops `prompt:'consent'` (`driveAuth.js:153`) → default prompt. Returning users get the account chooser at most. Device-verify a full connect → disconnect → reconnect cycle.

**F5 — Drive-restore inventory confirm (workflow section).** Extract the file-restore inventory summary into a shared helper (`describeJournalInventory(payload)`); the Drive restore confirm pulls the (now tiny) journal first and shows the same inventory + the backup's local-formatted date before the destructive step.

**v0.99.1 verification (device):** journal on Drive is KB-sized after push; a second push with unchanged library uploads no blobs (network tab); kill + relaunch the PWA → auto-backup resumes without user action (or shows the honest paused line + one-tap resume); reconnect shows no consent screen for a returning user; Drive restore shows the inventory; legacy journal (embedded blobs, from pre-v0.99.1) still restores correctly.

## Part 3 — v0.99.2 "Multi-device merge" — schema v13

The heavy release: v0.98.6-class care. One commit per fix.

**F1 — `updatedAt` stamps (schema v13).** Entities gain `updatedAt` per C4: items, programs, routines, history entries, settings (whole-object stamp `settings.updatedAt`), and reflections via a **sidecar** `etudes-reflectionMeta` `{daily, week, month}`. Free notes already carry `updatedAt` (v11). **Stamping mechanism per A6 (choke-point wrappers).** Migration v13: default `updatedAt: 0` everywhere missing; unconditional idempotent live-load + import migration; `SCHEMA_VERSION = 13`.

**F2 — Newest-wins merge.** `mergeById`/`mergeHistory` compare `updatedAt` when both sides hold the same key (newer wins; tie/missing-both → local, preserving legacy behavior). Reflections: per-field newest via the sidecar stamps. Settings: newest whole-object. **Recorded limitations (accepted 2026-07-12):** per-spot merge stays item-level (two devices editing different spots of the same piece in one gap — newer item wins whole); `itemTimes`/`workingOn` keep their current merge rules (per-key local-wins / union) — time-accounting merge is genuinely ambiguous and F3-of-v0.99.0 shrinks the window.

**F3 — Deletion tombstones.** `coldState` gains `deleted: [{id, kind, deletedAt}]` (kinds: item, program, routine, note; retention per A10; rides sync payload + export under v13). Written at actual removal (for items: when the trash/undo window resolves to deletion; `undoDelete` removes the tombstone). Merge semantics: an entity is dropped when a tombstone for its id has `deletedAt > entity.updatedAt`; an edit **newer** than the deletion resurrects (edit-after-delete means the user wants it back); tombstone lists union with newest-`deletedAt` dedupe.

**F4 — Informed conflict modal.** `SyncConflictModal` gains: each side's last-edit time (local: max `updatedAt`/`localDirtyAt`; remote: the row's `updated_at`) rendered as local times, and a diff summary from a pure helper `diffStates(local, remote)` → "differs: 2 pieces, 1 note, today's reflection" (per-entity `structurallyEqual`). One added line of explanation: "Merge keeps the newer version of each piece and note." Device names are out of scope (no device-identity plumbing this run — recorded).

**F5 — O3 note.** No SQL changes in this release (v13 is client-side shape; `user_state` stores the blob unchanged). Adopt tracked-migrations discipline in the README/repo docs so the next real DB change goes through `supabase/migrations/`.

**v0.99.2 verification:** migration triad (fresh / v12-with-data / empty) ×2 (live-load + import). Two-device matrix (Mac + iPhone, real accounts): (a) same note edited both sides → newer body wins in both directions; (b) delete piece on A, unrelated edit on B → stays deleted everywhere; (c) delete on A, then B edits that piece *after* the deletion → resurrects (intended); (d) both reflections edited → newer wins per field; (e) conflict modal shows times + diff counts; (f) `updatedAt` never re-stamps on cloud-apply (sync twice, stamps stable). Tests: LWW comparator, tombstone merge, `diffStates`, migration idempotency.

## Cascade risks

| # | Risk | Binds | Mitigation |
|---|---|---|---|
| R1 | Naive T5 fix syncs every timer tick | 99.0 | F3's boundary-stamp design is explicit in this spec |
| R2 | Metadata-only push breaks old-journal restore | 99.1 | C2 asymmetric compatibility; explicit legacy-restore verification step |
| R3 | Non-reactive token gating patched, not fixed | 99.1 → 99.2 | C6 mandates reactive `driveReady` state, not re-check patches |
| R4 | Stamp wars: cloud-apply re-stamps entities | 99.2 | C4 + `applyingCloudRef` guard + verification (f) |
| R5 | Tombstones grow unbounded / resurrect wrongly | 99.2 | A10 bounds; `deletedAt > updatedAt` rule; matrix steps (b)(c) |
| R6 | Merge forks per path (Supabase vs Drive) | 99.2 → future | C3: one `mergeStates`, Drive-as-sync inherits |
| R7 | Schema creep outside v13 | 99.0/.1 | C5: only v0.99.2 touches persisted shape |

- **v0.99.1:** versions → `0.99.1`. CHANGELOG: *Drive backup continuity* — backups run again after every relaunch; the journal file is light; unchanged recordings aren't re-uploaded; restoring from Drive shows what you're restoring.

## Reconciliation addendum (2026-07-14) — binding over the base text

*The engineer's independent scope (`v0.99.0-2-scope-CC.md`, 2026-07-13, written blind) was compared against this spec per protocol. Convergence was high on every mechanism family (error map, preflight, payload flag, reactive token, boot renewal, LWW+tombstone semantics, no-fabricated-recency migration, shared inventory helper). The following amendments bind; each was verified in code by the architect before adoption.*

**A1 — Blob-coverage escalation is a hard prerequisite of F1/1.1 (from CC's G1; adopted, highest-priority catch).** Blob files reach Drive only in `'full'` pushes; a user whose blobs were written while the token was dead (the common post-relaunch case) has the embedded journal as their *accidental* blob backup — which F1 removes. Therefore F1 ships **with** coverage detection: on every `'json'` push, set-difference `idbAllKeys(store)` vs `manifest.driveFileIndex` keys; any missing blob escalates that push to `'full'` via the existing `coalesceFull` hook (`driveSync.js:49,162`). Without A1, v0.99.1 would *reduce* data protection.

**A2 — The connected marker is device-local, never `settings.driveConnected` (from CC's G2; adopted; amends C6).** `settings` rides the synced payload — the flag lies on every other device. Boot renewal keys off additive manifest fields `driveConnectedAt` + `driveAccountEmail` (shown in the Sync tab; makes wrong-account reconnects visible). `settings.driveConnected` is never gated on again; removal deferred past this run.

**A3 — Per-store skip policy replaces uniform size-compare (from CC's G3; adopted; amends F2/1.3).** pdfs / recordings / pieceRecordings are immutable per key (new content = new key) → index-existence skip, no hashing. refTracks overwrite the same key (`uploadRefTrack` keys by `itemId`, `useEtudesState.js:543`) → SHA-256 content hash (`crypto.subtle`, sequential) against additive manifest map `driveBlobHashes`; upload on mismatch. Recorded trade: Drive-side deletions aren't detected until restore (a "verify backup" action is a v0.99.5+ candidate).

**A4 — Silent-renewal timeout wrapper (from CC's G4; adopted).** The silent token path has no timeout (`driveAuth.js:174–200`) — boot renewal wraps it (`silentRenewWithTimeout(~10s)`), leaving the underlying function and every iOS gesture invariant untouched.

**A5 — T5 mechanism corrected; design extended (CC's §3 reframe; verified `useEtudesState.js:319,337,680`).** Timer seconds *do* push on stop/close/hide; the loss is the **boot-time conflict clobber** (dirty-marker gap → `localDirty=false` → silent apply-remote overwrites local `itemTimes`). F3's boundary-stamping stands, plus: a dirty-heartbeat on the existing 60s rollover tick while the timer runs; a 5-minute push heartbeat during active practice (crash insurance); a `pagehide` listener beside `visibilitychange` (iOS termination path). Per-second deps remain forbidden. Acceptance test targets the clobber: timer-only session → kill PWA → relaunch → seconds intact and cloud converges.

**A6 — Stamping via choke-point wrappers, not per-helper edits (CC's 2.1 mechanism; adopted; amends Part 3 F1).** `setItems`/`setPrograms`/`setRoutines` (and `setHistory`, per A9) are wrapped once at definition: a pure `stampChanged(prev, next)` ref-diffs and stamps only changed/new elements; `applyingCloudRef` is read *inside* the updater (synchronous during cloud-apply's setState — the guard cannot race; verified sound). Dozens of inline mutator call sites keep working unchanged; per-helper stamping is the error-prone path and is rejected.

**A7 — Completeness checklists (from CC's flags 6–7; adopted as PR checklist items).** (i) Every new manifest field (A2, A3) must be added to `manifestSnapshot()` (`driveSync.js:59–68`) *and* the fresh-device restore mapping (`:337–343`) or it silently vanishes. (ii) Every v13 state key (`deletions`, `reflectionMeta`, `settings.updatedAt`) must be added to `applyCloudState`, `coldState`, the export payload, and `applyJournalPayload` — the apply path rebuilds state field-by-field and drops unknowns. (iii) Grep-audit all `applyingCloudRef` producers and all ~30 `setConfirmModal` sites (`ackOnly` default-false = zero behavior change).

**A8 — Cross-version sync window recorded (CC's §2).** A v12 client pushing between migrations drops v13 fields (tombstones). Bounded (single user, PWA upgrade lag ~hours); documented in the v0.99.2 PR, not engineered around.

**A9 — Architect call on CC's flag 8: settings and history ARE in scope.** `settings.updatedAt` (whole-object newest-wins) and history-entry stamps (log edits are real user edits; same wrapper pattern) ship in v0.99.2 — the pristine bar says resolve the scalar/archival lottery too, and the marginal cost inside A6's mechanism is small. `itemTimes`/`workingOn` merge rules stay as-is (recorded limitation, unchanged).

**A10 — Tombstone retention: both bounds.** Prune > 90 days at rollover (CC) *and* hard cap 500 FIFO (base spec).

**A11 — Small reconciliations.** Payload flag named `includeBlobs` (boolean; CC's shape). Backup-success copy platform-neutral ("Backup saved." — iOS uses the share sheet, not downloads). Backup buttons pair with the Restore renames ("Back up to file" / "Back up to Drive") per Q7a. The same-class UTC slice at `useImportExport.js:478` (ZIP filenames) is batched into F5. Preflight adds the `navigator.onLine` short-circuit. Conflict modal threads `loadFromCloud`'s already-returned `updated_at` through the caller (currently discarded).

**A12 — Schedule adopted from the engineer's estimates (~14 days total: 2.5–3 + 5–6 + 6–7).** Revised plan: W29 = v0.99.0 merged + v0.99.1 built and PR'd; v0.99.1 merges early W30; v0.99.2 spans W30, merging early W31 after the two-device matrix. Still comfortable for the late-August ~v0.99.9 beta (Additions W31 → refinement band W32–33).

*Comparison verdict: the blind-derivation protocol earned its cost — four real catches (A1–A4) none of which either document would have carried alone, one audit-mechanism correction (A5), and one mechanism upgrade (A6). Base text + this addendum = the buildable spec.*
